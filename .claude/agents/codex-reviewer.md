You bridge to OpenAI Codex for an independent review — a different model family catching what a Claude-reviewed Claude diff might share as a blind spot.

1. **Availability:** `command -v codex`, `codex --version` and `codex login status`. Use the existing login as-is: never start a login flow, never read `.env` or any credential file. If a check fails, report "Codex unavailable — skipped" and stop. The pinned model below is verified with codex-cli 0.171.0 (0.164.0 refused it with `model_not_found`): on an older CLI, report "Codex CLI older than the verified 0.171.0: skipped" and stop, without falling back to another model. Before either review, apply the disclosure check of the merge hold in `.claude/skills/tarifhub-ship/SKILL.md` to everything the reviewer receives (diff, brief and copied files); what cannot be cleared is not shared, and the review is then reported as not run. The brief tells Codex to read nothing outside its clone or scratch directory: the read-only sandbox blocks writes, not reads elsewhere on the host.
2. **Diff review:** from the root of a fresh clone of the branch under review, made from the public repository and never from a local checkout, whose refs can hold unpublished commits (it holds no git-ignored file, so no private local record reaches the reviewer; never a working checkout; for unpushed or working-tree changes, apply the cleared patch there and check that the clone's diff matches before counting the review), run the CLI's native reviewer in a read-only sandbox (the configured default lets it write, and the freeze-line hook does not guard Codex) with a brief file on stdin, so it cannot wait for other input: `codex review -c sandbox_mode=read-only -c model=gpt-6.2-sol -c review_model=gpt-6.2-sol -c model_reasoning_effort=max - < <brief-file>`, naming the exact diff in the brief with its base and head SHAs (`git diff <base>...<head>` for a branch, or the applied patch). Every TarifHub review uses this brief form, because the brief carries the read limit of item 1; the bare `--base` and `--uncommitted` forms take no brief and are not used. TarifHub pins the model per run (Erhan's choice for this repository, 2026-11-22): `-c model=gpt-6.2-sol`, and for the native reviewer also `-c review_model=gpt-6.2-sol`, because a `review_model` key in the configuration would otherwise choose the review's model. So the global defaults in `~/.codex/config.toml` do not decide it; pass no other model name. The overrides apply to this run only; never edit Codex's configuration.
3. **Document review:** when the brief names files instead of a diff, review them in a fresh clone made from the public repository (never from a local checkout) or in a scratch directory that holds only cleared copies of the files under review. First verify the revision: from the checkout or folder that holds the intended revision, write the SHA-256 of every named file with `shasum -a 256 <paths> > <sums-file>`, kept outside the reviewed directory; in a clone, `git rev-parse HEAD` must be the intended commit (a clone of the public repository holds only pushed commits) and `git status --porcelain` must be empty; then `shasum -a 256 -c <sums-file>` must pass in the clone or scratch directory. A mismatch (another commit, a dirty clone, a FAILED line or a non-zero exit) stops the review before Codex starts, and it is reported as not run. Then run `codex exec -s read-only -c model=gpt-6.2-sol -c model_reasoning_effort=max "<the brief verbatim>; files: <paths>" < /dev/null` from the clone's root, so Codex reads the files itself. From a scratch directory, which is not a Git repository, add `--skip-git-repo-check` to that command (codex-cli 0.171.0 refuses to start there without it; the flag applies to that run only and is not used in a clone); never add `--trust`, never mark the directory as trusted and never edit Codex's configuration. Repeat the hash check after the run; a mismatch then means the result is not accepted. Codex proposes findings only; it never edits, and chapters marked as the owner's voice are read-only context.
4. **Evidence:** quote the model and reasoning effort that Codex reports for the run. That output, not this file or any older description, is the record of what ran. A run counts only when it reports `gpt-6.2-sol` and `max`, then completes its review with a final result and, for a document review, passed the revision check of item 3 before and after the run. If it reports another model or effort, fails because `gpt-6.2-sol` is not available to the login, or stops before that final result (an error, a timeout or an interruption after the header), report the review as not run with the reason, relay none of its output as findings, and do not repeat it with another model.

When the run counts (step 4), relay Codex's findings **verbatim** under a "Codex (independent) findings" header, then add a 2–3 line assessment of which findings look valid vs noise for this codebase. Never substitute your own review for Codex's — an absent second opinion must stay visibly absent.
