Ship the current change. Commit, push, open a PR or merge only when Erhan has explicitly asked for that step in this session; without that request, stop after step 5 and leave the working tree as it is.

1. **Confirm scope.** State what the change is meant to do, then list what it touches: `git status --porcelain` and `git diff --name-only main...HEAD`. Anything beyond the request, or an unclear request, is a question for Erhan before you go on.
2. **Run the applicable checks** from the AGENTS.md definition of done: `uv run --no-sync pytest -q` and `uvx ruff check .` in each touched service; `mkdocs build -f docs/mkdocs.yml --strict` and `python3 tools/cas_check.py --ci` when `docs/` changed; `npm run lint && npm run build && npm test` when `apps/tarifguard/` changed. A result already obtained counts only under the reuse rule at the end of the definition of done. Start containers only when the change alters runtime behaviour the offline suites cannot show, or when Erhan asks. Quote failures verbatim, fix, re-run.
3. **Review the change.** Read the full diff yourself. Confirm that neither listing from step 1 contains a freeze-line path. For a `services/` diff, work through the determinism-boundary checklist (`.claude/agents/determinism-auditor.md`); for secrets, input parsing, the de-identification seam or internet-facing code, the security focus list (`.claude/agents/security-reviewer.md`). When a second model family adds something concrete, run the Codex review yourself (read-only commands in `.claude/agents/codex-reviewer.md`). Dispatch a reviewer agent only when Erhan has authorized delegation for this task (CLAUDE.md) and a fresh context adds something concrete; give it step 2's results to reuse instead of re-running them, and block on its result.
4. **PR and CI, only on explicit request.** Branch first if on `main` (`feat/…|fix/…`), make small Conventional Commits, open the PR with `gh pr create` (what and why, checks run, review notes; `--draft` and the disclosure check of the merge hold below whenever a hold could apply), then `gh pr checks --watch`; the determinism-boundary step must show in the CI log. Merge with `gh pr merge --squash --delete-branch --match-head-commit <reviewed head SHA>` only when Erhan asked for the merge, every merge condition in the AGENTS.md Git convention holds and no merge hold (below) applies; re-check each one immediately before merging.
5. **Report.** Files changed; checks run with their results; results reused and why they still apply; checks skipped and why; review findings and what happened to each; remaining risks; git state (uncommitted, committed, pushed, PR open, merged).

**Merge hold for an escalated P1.** From the moment a P1 review finding goes to Erhan for his decision:

- **Affected PRs.** Every PR that affects the finding, or could expose the same information, is held: open it as a draft, convert one that is already open at once (`gh pr ready --undo`), confirm that auto-merge is off (`gh pr view --json autoMergeRequest` shows `null`), and never mark it ready or merge it. Only Erhan's explicit decision on that specific finding releases it; a notification, his silence, a general authorization to merge, a new revision or a narrower clean review does not.
- **Unclear PRs.** A PR whose independence is unclear is held as a precaution, or split: in draft (converted at once if already open) with auto-merge off. It leaves that hold once the lead has established, for its current diff, that it does not affect the finding and has written down why (privately when the reason would reveal the finding); it then merges under the normal conditions. Check again after every new commit.
- **Publication.** A draft is public. Before every push, PR creation or update, check whether the change, read together with what is already public, could expose the finding; if it could, keep it local or split out a part that cannot. The same check applies to everything a reviewer receives (the diff and any copied inputs): what cannot be shared is not shared, and a review that cannot see the exact change counts as not run.
- **One record, and sessions without it.** The hold carries across sessions and handoffs until Erhan decides. Its one authoritative record is the lead's git-ignored memory index in the primary checkout (`.claude/agent-memory/lead-engineer/MEMORY.md`). A session that cannot read that file (another harness, another checkout or clone, a session that is not the lead) cannot know whether a hold is pending: before any public write to the repository or its issues (push, PR creation or edit, comment, marking ready, merge), it asks Erhan, and goes on only when he confirms that no pending hold covers that exact content.
- **Privacy.** The finding's private detail (the case, the relationship and how to derive it) stays out of public issues, commits, PRs and reviewer prompts, before and after his decision; public text names a hold or its outcome only in neutral words. Independent reviews run from a fresh clone, which holds no git-ignored file, and the brief tells the reviewer to read nothing outside it; Codex's read-only sandbox blocks writes, not reads elsewhere on the host, so that limit rests on the instruction (no isolation at the operating-system level is built).
- **Enforcement** is this procedure, `.claude/agents/lead-engineer.md` and the merge conditions in AGENTS.md, not GitHub: as of 2026-11-24 `main` has no branch protection and no ruleset, and the repository's auto-merge setting is off. GitHub refuses to merge a draft PR, but anyone with write access can mark it ready.

If a step fails and one fix attempt does not resolve it, stop and report instead of looping.
