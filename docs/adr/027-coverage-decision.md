# ADR-027: Make the evidence-seeking agent's coverage decision explicit (Phase 4, condition D)

*Status: Proposed (evaluation design frozen 2026-11-25; implemented and tested offline; not run live) · Date: 2026-11-25 · Decider: Erhan (+ AI-assisted analysis)*

## Context
The platform inherited from the earlier course (baseline `530f850`, 3 July 2026) has no commentary retrieval and no agent. This course added cited answers over the BAG commentaries ([ADR-025](025-commentary-retrieval.md)) and the bounded evidence-seeking agent ([ADR-026](026-commentary-evidence-search.md)). The measured Phase 3 baseline is the comparison of fixed top 5, fixed top 10 and the agent on six frozen cases, one run per cell, rated blinded by one reviewer ([evidence](../evidence/2026-11-21-phase3-E-comparison.md)): on the primary set of five cases the agent's overall verdict was `yes` on 5, fixed top 10's on 4 and fixed top 5's on 3, at a calculated cost of the same order. The agent searched in every cell, also where its first five passages already held all required evidence, so whether it can tell when not to search stayed untested. For Phase 4 Erhan took variant 1 of the course, extending the agentic behaviour, as the working direction (issue #62, 2026-11-24). The only signal the Phase 3 instruction gives is generic ("if the passages do not state something the question asks for ... use the tool"), and nothing records what the model judged covered.

## Decision
Proposed: a fourth comparison condition, D (`coverage`), is the Phase 3 agent with an explicit coverage decision and nothing else changed. In the same call as its action the model lists the parts the question asks for (at most four), each covered by named passages it has received or missing; it answers when every part is covered and otherwise searches for exactly one missing part, named by its number (`search_for`). Code checks the record before anything is ranked: a coverage that is malformed, names a passage not supplied, or a `search_for` that names no missing part is refused as a tool error that uses the round, like any refused search; a valid request runs the unchanged search of ADR-026 on its usual arguments. An answer carries the coverage beside the unchanged Phase 2 answer object; the answer is accepted or rejected exactly as the agent's, and the coverage is only checked and recorded (codes and counts publicly, the text locally), so blinded reviewers see the same answer format for every condition. The tool is offered by capacity alone, exactly as for C, never because of D's own record. D keeps C's initial top 5, retrieval, edition filter, ten-passage total, two searches, three calls, model, settings, books and admission. The texts, schemas and checks were frozen with the evaluation before this code existed (`tools/commentary_rag/phase4/conditions.md`, hashes in `results/2026-11-25-phase4-freeze.json`), and tests compare the code with those hashes. The comparison runner gains a Phase 4 design (B, C, D), whose public record names no passage, and a deterministic scorer implements the frozen search measures and outcome rules (`phase4/rubric-and-thresholds.md`). B and C send byte-identical requests to those before D existed.

## Alternatives weighed
- **Coverage only in the search request:** a direct answer would leave the decision unrecorded, and the cases where not searching is right are the ones the hypothesis is about.
- **A separate coverage call before each action:** an extra call per decision changes the call bound, the cost and the comparison with C.
- **Withholding the tool once the coverage says complete:** D could then lower its count of missed searches by misjudging coverage; capacity alone decides when the tool is offered, and missed searches are counted against the frozen evidence.
- **D starting from the top 10:** with the ten-passage total held fixed it could never search; it needs other limits and stays open.
- **A typed-judgement replay of the coverage decision through Jev:** priced separately as an optional follow-up and not authorised.

## Consequences
- (+) The decision to search is recorded per call and checked in code. The frozen design defines the test of the hypothesis (fewer unnecessary searches without more missed useful ones and without a loss of answer quality) with B and C unchanged, on the same books, against thresholds fixed before any result; the strata of a case set follow from the shared ranking, and whether each threshold can be assessed follows from the run's decision points and, for R1, from the ratings; both are reported with the results.
- (+) Tested offline at the provider boundary: the frozen texts and schemas by hash, direct answers, justified gaps, valid targeted searches, invalid passage references in searches and answers, searches for covered parts, malformed records, no new evidence, a full passage budget, answers without an answer object, and B's and C's unchanged requests ([§13](../arc42/13-test-strategy.md)).
- (-) More output per call (the coverage record), and D's request differs from C's in instruction, tool schema and answer format, so the comparison measures the conditions as built, not one factor at a time.
- (-) Not evaluated: no live call has used D's schemas (an integer field in a strict tool, the coverage beside the answer object), so the provider contract for them is unverified.
- (-) The current books do not admit the frozen design: one case under B, C and D is admitted at USD 10.3488, so 19 cases need USD 196.6272 of headroom at once, more than the USD 100 limit for Phases 2 and 3 leaves; and a cell already in the books is never run again, so repetitions need their own identity. Books, cap and admission for a live repetition are Erhan's decision; this increment changes none of them.
- (-) The cases are AI-drafted and checked by the lead, one person selected them as a set and rates the answers, and blinding is partial.

## Decision status
Proposed. Acceptance follows the frozen outcome tables after a live evaluation that Erhan has not yet authorised; until he records a decision, the status stays Proposed.
