# ADR-028: Phase 4 books: a separate cap, the repetition in the identity, admission by case

*Status: Accepted (decided by Erhan on 2026-11-26; its operational fixes approved by him on 2026-11-27; implemented and tested offline, rehearsed with a simulated provider; not run live) · Date: 2026-11-26, amended 2026-11-27 · Decider: Erhan (+ AI-assisted analysis)*

## Context
The spending protection of the evidence-seeking agent ([ADR-026](026-commentary-evidence-search.md)) books every call of every condition in one active ledger beside the recorded Phase 2 ledger, under one aggregate limit of USD 100, and admits a comparison only when the worst case of all its cells still to run fits at once. The frozen Phase 4 evaluation ([ADR-027](027-coverage-decision.md), proposed) runs B, C and D on 19 cases: one case is admitted at USD 10.3488 (1 + 3 + 3 calls at the input cap), so the matrix needs USD 196.6272 at once, more than those books leave (USD 92.939448). A cell already in the books is never run again, so a repetition also needs an identity of its own. On 2026-11-26 Erhan decided to make one exploratory repetition runnable under a separate cap of USD 40 (expected about USD 16.6, high scenario USD 31.24: calculated from recorded usage, not invoiced).

## Decision
Phase 4 gets its own books: `results/phase4-ledger.jsonl` beside the Phase 2 and Phase 3 ledgers, under the same folder lock, with a limit of USD 40 pinned in code (`evidence_agent.PHASE4_LIMIT_USD`) and in the ledger's first line, and nothing else counted beside it. Every Phase 4 cell is booked under (repetition, case, condition), with the call IDs `<case>-<condition>-r<repetition>-call<n>`; the code admits repetition 1, the conditions B, C and D, and books D nowhere else; a frozen Phase 4 case (the freeze record's 19 IDs with their question hashes and editions), by its ID or its question, is refused in the Phase 2 and 3 books whatever the condition or the entry point, and booked in Phase 4's books only under its frozen identity. The books' first line pins their time budget beside their limit. Since 2026-11-27 the first call's request is saved first, and the pin and that first reservation are then written as one accounting event under the lock: the ledger is created holding both lines or not at all, so a failed request write leaves neither, a ledger write that leaves the ledger absent leaves neither (a rerun may correct the budget), and a write whose result is not known stops the run before anything is sent. A cell with another budget is refused. The comparison runner's Phase 4 design takes only the frozen runner input (its SHA-256 pinned) and a corpus whose PDFs have the frozen SHA-256 values and runs its cases in their order, B, C and D per case, in one invocation; a cell that booked nothing stops the run, so a rerun keeps the frozen order. Since 2026-11-27 both comparison designs claim the run's local folder before the client is built or the model loads (the folder, then a claim file naming the design and a token only that invocation holds): a second invocation under the same tag, of either design and in either start order, is refused before it loads anything, and a failure while the claim is written or before the first cell gives back only that invocation's own unused claim, never another's claim or an artifact. Also since 2026-11-27 a Phase 4 cell that an unexpected error or an interruption ends is recorded by the runner before the run stops: the calls that run demonstrably sent (its own saved request and response, consistent with the books) make it a cell that ran and failed, as the frozen rubric counts it, and the searches those calls ran are kept as the cell recorded them and scored like any failed cell's; a reservation without that proof confirms nothing, nothing after the last recorded step is inferred, and the scorer counts such cells apart. Before each cell, under the lock, the worst case of the case's cells still to run must fit beside everything committed in those books (settled calls at their cost, calls kept at their reservation, reservations without a settlement), so a fresh case starts only when its USD 10.3488 fits, and a case that does not fit stops the run before anything of it is sent. The books themselves hold back the case's other cells not yet booked at every cell's admission, so a caller that starts a fresh case with any condition needs the whole triplet's headroom. The ceiling, reservations, settlements, persistence and the strict reading of the ledger are ADR-026's code; the Phase 2 and 3 books and B's and C's requests stay byte-identical, and the Phase 3 design changes only in claiming its tag (since 2026-11-27). The scorer takes the frozen gold file only, every record names its repetition, and a repetition is complete only for the frozen cohort, as the scorer itself finds it, never on a caller's word.

## Alternatives weighed
- **Phase 4 in the Phase 2 and 3 books:** the frozen matrix does not fit them at once, and batches admitted one by one would spend their allowance with no cap of Phase 4's own.
- **The whole matrix admitted at once under a larger cap:** USD 196.6272 of headroom for a run expected at about USD 16.6 binds a cap far above any planned spend.
- **A repetition or batches chosen on the command line:** a new tag, a subset or another order of the cases could bypass the case admission or make an incomplete repetition look complete; the repetition is fixed in code and the cases file pinned.
- **Sending again a cell whose booking is unresolved:** its call may have reached the provider; it is never sent again, and its case stays incomplete.

## Consequences
- (+) No Phase 4 call can be sent outside the USD 40 books, and the Phase 2 and 3 allowance is not used. An interruption, a restart or a concurrent invocation cannot send or book a cell twice: each cell's identity and each reservation are checked under the lock (tested offline and rehearsed with a simulated provider, [evidence](../evidence/2026-11-26-phase4-repetition-books-offline.md)).
- (+) A repetition is complete only when every frozen case ran under B, C and D; an incomplete one gives no threshold verdict, whatever the tag or the batch.
- (-) A call whose sending is unknown (an interruption while it was on the wire) stays open at its reservation, and a call released before sending stays released; either confirms no sending, so a cell with no other confirmed send leaves its case incomplete. A replay failure that C and D share (a lone surrogate the model escaped in a tool input) still ends the run after the cell's calls are settled; since 2026-11-27 that cell is recorded as run and failed, with the search its sent call ran, so a restart can complete its case and that search counts as a decision (in T3, and beside it in the supplemental A1 report, as any search would); the call the replay never made is no decision point. A send that got no response leaves this run no proof of it, so its cell counts as run only through an earlier call that has one.
- (-) Under the high cost scenario (every cell at the highest recorded cost of its condition, USD 1.644404 per case) the 19th case starts with about USD 0.05 to spare; one call kept at its reservation or one open reservation can stop the run before the last case and leave the repetition exploratory.
- (-) A second or third repetition needs another decision: a higher cap and the repetitions admitted in code.

## Decision status
Accepted by Erhan on 2026-11-26 for one exploratory repetition; implemented and tested offline and rehearsed with a simulated provider. On 2026-11-27 Erhan approved the operational fixes for the open points of the third independent review round: the time-budget pin and the first reservation written as one event after the request is saved, the output tag claimed exclusively by both comparison designs before the model loads (with an unused claim given back only by its owner), and the confirmed sends of an aborted Phase 4 cell kept at the runner and scored as run and unsuccessful. The USD 40 limit is a technical cap of the books: approving it, or these fixes, authorizes no expenditure. A live run needs his separate decision.
