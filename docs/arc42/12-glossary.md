# Glossary

The terms that recur across this report, each defined as implemented in the repository, not in the abstract.

| Term | Definition |
|---|---|
| **Freeze line** | The architectural boundary that separates AI-assisted, pre-freeze harmonisation (L0) from the deterministic, read-only serving layers below it (L1+). No AI computes or mutates a billing value at serve time. |
| **Freeze** | The pipeline step (`versioning/freeze_record.py`) that stamps a record's `record_hash` and makes it immutable. Re-freezing an already-frozen record raises `ValueError`. |
| **record_hash** | The SHA-256 hash over a record's sorted canonical content (excluding `record_hash`, `created_at`, `version`). It is the integrity anchor and the idempotency key, `UNIQUE` in the database. |
| **ai_map** | The single live-AI seam inside the services (`mappers/tariff_mapper.py`), running only pre-freeze: it wraps the deterministic `map_raw` and may fill missing non-billing fields via schema-constrained structured output. |
| **fill-only** | The constraint on `ai_map`: it may only add a value to an empty non-billing field (FR/IT designation, category) and never overwrites an existing value or touches a billing value. |
| **gap-gate** | The deterministic check that decides whether `ai_map` calls the model at all. When nothing fillable is missing it skips the call entirely (the EAL live run made zero API calls over 1 279 complete rows). |
| **fill-reuse** | The mechanism (`ADR-005 addendum`) that carries a prior frozen version's AI fills forward with no model call when the deterministic pre-fill content is unchanged, making re-ingest reproducible despite non-byte-stable live fills. |
| **TariffRecord (canonical model)** | The single Pydantic v2 model (`models/tariff_model.py`) used end to end. Its field set is locked additive-only ([ADR-003](../adr/003-canonical-record-model.md)) and mirrors `db/schema.sql`. |
| **harmonisation** | The process of mapping heterogeneous Swiss tariff sources (XLSX, FHIR) into the one canonical `TariffRecord` shape. Heterogeneity is absorbed in source adapters so the value path stays a single deterministic shape. |
| **confidence score** | A deterministic harmonisation-confidence value in [0, 1] computed per record (`confidence/scorer.py`). Records below `TARIFHUB_REVIEW_THRESHOLD` (default 0.85) are flagged for review. |
| **requires_review / review queue** | The boolean flag set when confidence is below threshold or validation fails. The record still freezes carrying the flag, and the set of flagged records is the review queue routed to a human. |
| **audit_log (append-only)** | The lineage table keyed by `record_hash`. Every pipeline outcome (`freeze`, `freeze_skipped_idempotent`, review decisions) appends exactly one immutable event, never an update or delete. |
| **versioning** | The immutable-update model: a frozen record is never edited. A correction or a new source version produces a new row with a new `version` and `record_hash`, `UNIQUE(tariff_system, tariff_code, version)`. |
| **determinism boundary** | The architectural rule enforced by an AST test (`test_serving_boundary.py`, `test_determinism_boundary.py`) that statically proves no LLM client is importable on any value-path module. CI fails otherwise. |
| **EAL (BAG Analysenliste)** | The Swiss federal laboratory-analysis tariff list, ingested as a flat trilingual XLSX (three parallel DE/FR/IT sheets joined by position number). Values are tax points. |
| **SL (BAG Spezialitätenliste)** | The Swiss federal list of reimbursed medicinal products, ingested as hierarchical FHIR R5 NDJSON (an IDMP resource graph keyed by GTIN). Values are retail prices in CHF. |
| **TarifCore (L1 serving)** | The read-only serving API (`services/serving/`): list/get tariffs, point-in-time and diff, deterministic semantic search, record-grounded explain, and a FHIR R4 read adapter. No write path. |
| **TarifMCP (L1 MCP)** | The Model Context Protocol server (`services/mcp/`) exposing `search_tariffs`, `get_tariff`, `explain_record` as read-only httpx proxies that return the serving API's frozen records verbatim. |
| **TarifIQ (L2 intelligence)** | The rules service (`services/intelligence/`), an offline-tested scaffold that is not part of the graded MVP value path: deterministic combinability checks over a frozen, content-hashed rule set, a TARMED→TARDOC crosswalk lookup over a frozen table, and pre-freeze rule validation. It reads frozen records only (a bundled snapshot by default, `TARIFIQ_OFFLINE`), no endpoint calls a model, and its one AI seam (`ai_rule_suggest`) is a placeholder that makes no live call. |
| **TarifGuard (L3 console)** | The demo console (`apps/tarifguard/`, Next.js, over server-side BFF routes): master-detail search, frozen-record detail, a human review form, a labelled AI explain panel, and a structural coding-check page (existence, review flag and validity window per position, no combinability verdict) that [ADR-013](../adr/013-demo-scope.md) accepts as a demo extra. It renders frozen values verbatim and computes nothing of its own. |
| **point-in-time / as_of** | The query that returns the frozen version of a key that was valid on a given date (`?as_of=<date>`), selected by `valid_from`/`valid_to` with the highest qualifying version. Returns 404 if none was valid then. |
| **diff** | The serving query (`/diff?from=&to=`) that returns the field-level delta between two frozen versions of one key, with both `record_hash`es included. It reports changes, never recomputes a value. |
| **AL edition** | One dated publication of the BAG Analysenliste, identified by its effective date in the tracked manifest (`data/manifests/bag-al.json`), which pins its full-list workbook by SHA-256 ([ADR-021](../adr/021-al-manifest-import.md)). Its stored records carry `valid_from` = the effective date and `source_version` = `BAG AL YYYY-MM-DD`; a record's `version` never identifies an edition. |
| **edition member** | For each position of an AL edition's full list, its earliest stored version with that edition's `valid_from`: the one the import froze from the file. Later versions of the same date (a review correction, an AI re-fill) are its successors, never another edition. |
| **edition comparison** | The deterministic, read-only comparison of two AL editions (`--manifest ... --compare FROM TO`, [ADR-023](../adr/023-al-edition-comparison.md)). It is refused unless both editions are stored completely and match their verified full lists, pairs edition members by code (not by version number, as **diff** does) and classifies positions only by the fields the frozen record carries. Beside that classification it lists the **workbook text changes** of selected German columns the record does not carry, with their **text coverage** ([ADR-024](../adr/024-al-workbook-text.md)), and names every other workbook column. It reports frozen values and published texts and computes none. |
| **added / removed / changed / unchanged position** | The four classes of an edition comparison. Added: listed only in the later edition's full list. Removed: listed in the earlier edition's verified full list and absent from the later one; a list fact, not a legal repeal, a deleted record or a changed `as_of` result. Changed: listed in both, with a different value in a compared field. Unchanged: listed in both, with equal values in every compared field; it may still have **workbook text changes**, which are listed separately, and the other workbook columns the records do not carry are not compared. |
| **workbook text change** | A difference in one cell's text between the verified full lists of two AL editions, for a position listed in both, in a German column the edition comparison reads as published text: `Limitationen`, `Bemerkungen`, `Kumulierbarkeit` and the **laboratory flags** ([ADR-024](../adr/024-al-workbook-text.md)). Two texts are equal when they match after Unicode NFC normalisation and whitespace folding; any other difference, in words, case, punctuation or digits, is a change. It states what the published cells say, not a changed rule or entitlement (`Oui` to `Ja` is a text change), and it never makes a position changed. |
| **text coverage** | How much of the requested published text an edition comparison could compare: complete when every requested column was compared in both editions, partial when an edition has a requested column missing, named by two headers or holding a value that is not text (that column is compared in neither edition and counts nowhere), unavailable when no column could be compared, and then nothing is counted, not even as unchanged. |
| **laboratory flag** | A `Ja`/`Nein` column of the AL full list that says, per position, which laboratories may bill it to the mandatory health insurance (handbook 6.13 and 6.14). Under the banner "Zugelassene Laboratorien gemäss Artikel 54 KVV": eight columns, each a type of laboratory billing for its own needs (`für Eigenbedarf`) or on external order (`im Fremdauftrag`), plus `Hausbesuch` (billable when a physician performs it on a home visit) and `Schnelle Analyse` (a rapid analysis). Under the banner for practice laboratories of physicians with specific further-education titles: eleven titles, such as `Gynäkologie und Geburtshilfe`. The discipline and analysis-group columns and the **prescriber flags** are not laboratory flags. |
| **prescriber flag** | A `Ja`/`Nein` column of the AL full list that says whether a provider other than a physician may prescribe the position: `Hebammen` (midwives) and `Chiropraktoren oder Chiropraktorinnen` (handbook 6.15, Article 62 KVV). These providers are not laboratories: a laboratory under Article 54 KVV performs the analysis. The edition comparison does not compare these columns. |
| **BAG commentary** | The BAG's German explanation of the changes in one AL edition, published as a PDF beside the list and pinned per edition by SHA-256 in the AL manifest. The corpus of the commentary RAG pilot ([ADR-025](../adr/025-commentary-retrieval.md)). |
| **commentary passage** | A retrievable unit of a BAG commentary: the text of one section on one page, never crossing a page, carrying its edition, document hash, page, printed page label and section. |
| **edition filter** | Retrieval over an explicit selection of AL editions: passages of unselected editions are never candidates, so a filtered ranking cannot return another edition's passage. |
| **reciprocal rank fusion (RRF)** | The pilot's hybrid ranking: each passage scores the sum of `1 / (60 + rank)` over its BM25 rank and its multilingual-e5 rank. |
| **citation membership** | The deterministic check that every passage an answer cites was among the passages supplied for that answer: the request's passages in the fixed pipeline, and every passage supplied in the conversation (the fixed ones and those its searches returned) for the **evidence-seeking agent**. It does not show that the passage supports the claim; that is a human judgement. |
| **abstention** | An answer with status `insufficient_evidence`: the passages received do not state what was asked. It means only that, not that no tariff or change exists, and on a retrieval miss it does not make the question answered. |
| **commentary search** | The one read-only search a model may request beyond the passages of the fixed retrieval ([ADR-026](../adr/026-commentary-evidence-search.md), proposed): it ranks the passages of the editions selected for the question and returns, from the ten best, passages the model has not yet received, within the **passage budget** and the **search rounds**. The model chooses only what to search for and, optionally, fewer of the selected editions. Built and tested offline; only the **evidence-seeking agent** calls it, which ran one live search in its one live run (dev case D1, 2026-11-20). |
| **evidence-seeking agent** | The loop that lets the model answer one question from the passages of the fixed retrieval or first run up to two **commentary searches** for what they do not state, then answer in the same schema, citing only passages it received ([ADR-026](../adr/026-commentary-evidence-search.md), proposed). Built and tested offline, with every call accounted in the **spending ledger**, and run one question at a time by the one-question runner (`run_question.py`); it has called the provider in two runs (dev case D1, 2026-11-20, and the comparison of E1 to E6 under the **comparison conditions**, 2026-11-21). Not to be confused with the AI coding agents of the development workflow (`AGENTS.md`). |
| **search round** | One commentary-search request for a question, whatever its outcome: a refused or failed request uses its round too. A question has at most two. |
| **spending ledger** | The append-only record of what the pilot's model calls committed: a reservation at the request's ceiling before it is sent, then one settlement, at the cost calculated from the reported usage or, when the usage cannot be priced, at the whole reservation, kept as committed exposure. Calculated costs, not an invoice. The recorded Phase 2 ledger is closed and counts with all it committed; the **evidence-seeking agent** writes one active ledger beside it, and both share one aggregate limit of USD 100. |
| **admission check** | The check before a question of the **evidence-seeking agent** starts: its worst case, every allowed call at the input cap and at its ceiling (the same ceiling its reservations use), must fit beside everything the **spending ledger** has committed. One call for a fixed **comparison condition**, three for the agent. A check, not a charge. |
| **comparison condition** | One way of answering a question in the Phase 3 comparison, fixed in code ([ADR-026](../adr/026-commentary-evidence-search.md), proposed): A (`fixed5`) and B (`fixed10`) send the Phase 2 request with the question's hybrid top 5 or top 10 once, without any tool; C (`agent`) is the **evidence-seeking agent** from the top 5; D (`coverage`, Phase 4, [ADR-027](../adr/027-coverage-decision.md), proposed) is the agent with the **coverage decision**. All share the model, settings, question, editions, ranking and answer checks. |
| **coverage decision** | Condition D's record, in the same call as its action, of the parts a question asks for (at most four) and whether the passages received so far state each one (covered, with their IDs, or missing); a search must name a part marked missing ([ADR-027](../adr/027-coverage-decision.md), proposed). Code checks it; it never decides whether the tool is offered and never rejects an answer. |
| **decision point** | In the Phase 4 rubric, a generation call of a C or D cell before which the cell still has search capacity (a later call, a search round and passage budget left), judged on the passages supplied immediately before it, never on whether the tool was offered or on D's own coverage record. |
| **unnecessary search attempt** | Phase 4 amendment A1 (2026-11-26): at a no-search-needed **decision point**, an executed search or a refused model search request, counted once per point for C and D alike and reported beside T3 over T3's own denominator, executed and refused apart. A report, not a threshold: T3 itself counts executed searches only. |
| **repetition** | One run of the whole frozen Phase 4 case set under B, C and D ([ADR-028](../adr/028-phase4-books.md)). It is part of every Phase 4 **cell**'s identity in Phase 4's own books (call IDs `<case>-<condition>-r<repetition>-call<n>`); the code admits repetition 1 only. It is complete when every case ran under all three conditions; an incomplete one gives no threshold verdict. |
| **cell** | One case under one **comparison condition**: the identity under which the **spending ledger** books its calls (`<case>-<condition>-call<n>`), each reservation recording the question's hash and the editions, since one case ID names one question over one edition selection. A cell already in the ledger is never sent again; the D1 run of 2026-11-20 is D1's agent cell, recorded without its question. In Phase 4's books the identity also names the **repetition**. |
| **aborted cell** | A Phase 4 **cell** that an unexpected error or an interruption ended inside the agent's loop, recorded by the comparison runner before the run stops (since 2026-11-27): the calls its run demonstrably sent (its own saved request and response, consistent with the books) make it a cell that ran and failed, a non-success; a reservation without that proof confirms nothing. The searches those calls ran are kept as the cell recorded them and scored as any failed cell's (in T3, and in the supplemental **unnecessary search attempt** report A1 beside it); nothing after the last recorded step is inferred, and the scorer counts such cells apart. |
| **passage budget** | The most distinct passages one question may receive, the fixed retrieval's five included: ten, the same maximum count as a fixed top-10 context, though not the same token volume, compute or cost. |
| **FHIR R4** | The HL7 interoperability standard. The serving layer offers a read adapter that maps a frozen record to a `ChargeItemDefinition` and a tariff system to a `CodeSystem` without altering any value. |
| **de-identification seam** | The console's server-side scrubber (`lib/deident.ts`, ADR-012), the only sanctioned builder of a model-bound payload: the explain seam forwards a tariff code only and scrubs any free-text context. |
| **pgvector** | The PostgreSQL extension that stores the 1024-dim embedding column (`vector(1024)`, HNSW cosine index) and runs the semantic-search ranking (`<=>`) on the real engine. |
| **multilingual-e5** | The multilingual-e5-large embedding model (1024-dim) used for cross-lingual semantic search. It is asymmetric: indexed documents use a `passage:` prefix and queries use a `query:` prefix. |
